STEP 01

Create a free cloud database

MariaDB’s current documentation lists a Free Developer Tier capped at 10 MCU-hours per month; the database pauses when that allowance is used. Only the default server version is offered on that tier. Check the console’s price and version before creating it. If a free option is unavailable, use the local route below.

  1. Create or sign in to MariaDB Cloud. Choose its explicitly free developer database. Avoid a paid provisioned service or a paid version upgrade.
  2. Open the service’s Connect instructions. Record the hostname, port, database name, and administrator credentials privately. Use the displayed port; it may differ from 3306.
  3. Keep TLS enabled. Add your current computer’s IP to the database allowlist so your SQL client can initialize it.
  4. In Render, open your Studio service → Connect → Outbound. Add all displayed CIDR ranges to the database allowlist. These are Render’s shared regional ranges, not a unique app identity. Keep TLS and database authentication enabled.

See MariaDB connection guidance and Render outbound IP guidance. Your laptop’s localhost database cannot be reached by this Render service.

STEP 02

Prepare a fresh tutorial schema

Connect with a MariaDB-compatible SQL client using your provider’s verified TLS settings. Select a new empty schema, such as magics, in the provider console or with your administrator. Run this capability check first:

SELECT VERSION();
SELECT VEC_DISTANCE_COSINE(
  VEC_FromText('[1,0,0]'), VEC_FromText('[1,0,0]')
) AS distance;

Expected distance: 0. Community 11.8 LTS is the app’s baseline; native vectors require Community 11.7+ or Enterprise 11.4.5-3+. The probe and setup SQL confirm actual capabilities and permissions.

Download tutorial SQL ↓

Run the downloaded script once in the new schema as its owner. Studio accepts read-only queries, so initialization belongs in your admin SQL client. The script creates:

  • studio_documents: three rows with VECTOR(3) values and a cosine vector index.
  • studio_history: one system-versioned row with a salary change. It prints a timestamp named use_this_as_of to copy into Time travel.

These are small, manually chosen numeric vectors for checking the search pipeline. For semantic text search, use real embeddings with the same model and dimensions for stored documents and queries.

Create a read-only app user

Use the provider’s database-user controls or run the following as an administrator. Replace the password locally. If user creation is restricted, use the provider’s equivalent role controls; keep the administrator credentials out of Studio.

CREATE USER 'studio_reader'@'%'
  IDENTIFIED BY 'REPLACE_WITH_A_RANDOM_PASSWORD'
  REQUIRE SSL;
GRANT SELECT ON magics.* TO 'studio_reader'@'%';

The % host pattern relies on your network allowlist. Grant access only to the tutorial schema, with no FILE or EXECUTE privileges.

Reference: native vector tables and system-versioned tables.

STEP 03 · WORKSPACE OWNER

Connect the deployed app

Open Studio’s Render environment settings. Set the following values together, then save and deploy:

VariableValue
STUDIO_MODElive
STUDIO_TOKENA new random token of at least 24 characters. Share privately with trusted workspace users.
DB_HOSTProvider hostname, without a URL scheme
DB_PORTPort from the provider’s Connect panel
DB_NAMEmagics, or your selected schema
DB_USERYour read-only user
DB_PASSWORDThat user’s password, saved as a Render secret
DB_SSL_CA/etc/ssl/certs/ca-certificates.crt for a publicly trusted server certificate; see below for a provider CA

Generate your access token locally:

python -c "import secrets; print(secrets.token_urlsafe(32))"

For a private/provider CA, add its trusted CA certificate as a Render Secret File named mariadb-ca.pem, then set DB_SSL_CA=/etc/secrets/mariadb-ca.pem. Use the provider’s Connect instructions to choose the correct trust chain. Certificate verification stays enabled.

Follow Render’s environment and secret-file guide. Keep the web service on its Free plan. A cloud database is external to Render; its own free allowance applies separately.

One workspace, one database connection.

Live mode replaces the sample workspace for everyone at this URL. No credentials are collected from visitors. To keep a public demo and private live workspace side by side, deploy a separate service rather than changing this one.

STEP 04

Try vector search and time travel

Vector search

  1. Sign in with the workspace token.
  2. Open Vector search. Table: studio_documents, vector column: embedding, ID column: id, Top K: 3.
  3. Leave search text empty. Paste [1,0,0] as the query vector.
  4. Run search. ID 1 should rank first at distance 0, then ID 2, then ID 3.
Open vector search →

Time travel

  1. Open Time travel. Table: studio_history.
  2. Paste the exact use_this_as_of timestamp printed by setup, preserving microseconds. Use the database session’s time zone.
  3. Run history query. Salary should be 100000.
  4. Run SELECT * FROM studio_history in SQL workspace: current salary is 125000.
Open time travel →

Lost the timestamp? Run SELECT id, salary, ROW_START, ROW_END FROM studio_history FOR SYSTEM_TIME ALL in Studio. Choose an instant within the older row’s range, such as its ROW_START. A date before the first insert correctly returns no rows.

Using real text embeddings on the Free web service

The default deployment supports pasted numeric vectors without downloading a model. Local sentence-transformers models may exceed the Free service’s 512 MB memory allowance. Generate embeddings on your computer, store them in a matching VECTOR column, and paste a query embedding from the same model. Text input requires a server image with requirements-embeddings.txt installed and sufficient memory; it is optional and is not enabled in the Free demo image.

A real MariaDB database on your computer

This route uses your machine and needs no cloud database account. Install and start Docker, clone the repository, and open its studio/ folder:

git clone https://github.com/Jatin2567/MariaDB-magics.git
cd MariaDB-magics/studio

Create a private .env file containing three independently generated random values, each at least 24 characters:

LOCAL_ROOT_PASSWORD=REPLACE_WITH_RANDOM_VALUE_1
LOCAL_DB_PASSWORD=REPLACE_WITH_RANDOM_VALUE_2
STUDIO_TOKEN=REPLACE_WITH_RANDOM_VALUE_3
docker compose -f compose.live.yaml up --build -d

Open localhost:8081 and sign in with STUDIO_TOKEN. The bundled stack initializes MariaDB 11.8, loads the tutorial data, grants the app user SELECT only, and persists the database in a Docker volume. The database has no published network port; only the local Studio container connects to it.

Find the historical timestamp with the query in Step 4. Initialization scripts run only when the database volume is empty. To stop without deleting data:

docker compose -f compose.live.yaml down

This local stack does not connect the public Render app to your computer. Use the local app for local data, or the cloud route for Render.

Sign in and access

No Studio signup is required. The owner configures one database and one workspace access token in the hosting environment. In live mode, open Connection → Sign in with that token. The server issues an HttpOnly session cookie; the token is not saved in browser storage. Sign out ends that browser’s session. Render and MariaDB Cloud have separate provider accounts.

Everyone with the token has the same read access, including historical rows. This is a shared trusted workspace, not separate personal accounts. Rotating STUDIO_TOKEN invalidates existing sessions unless you explicitly configured a separate SESSION_SECRET. For private live data, share the token only with intended users.

If something does not work

Still says “Demo workspace”

Set STUDIO_MODE=live on the Render service and deploy the saved environment. An access token alone does not connect a database. Do not change mode until all DB variables are ready.

Connection denied, timeout, or TLS error

Check the provider host and port, schema grants, Render outbound CIDRs, free quota, and CA certificate. Use the hostname from Connect so certificate verification can match it. Open Render logs for the underlying database error; do not post credentials from logs.

Unknown VECTOR type, wrong dimensions, or no distance

Run the capability check. The server must support native vectors. All stored and query vectors need the same dimension; the tutorial uses exactly 3. Match a cosine search with a cosine index. Keep text empty when testing the numeric example.

Time travel is empty or the table is not versioned

Use studio_history and an instant after its first insert but before the raise. Historical rows exist only after versioning is enabled; earlier history cannot be reconstructed. Paste the setup timestamp in the database session’s time zone.

Cloud free quota used, or Render wakes slowly

The cloud developer database pauses after its monthly allowance is used. Render’s Free service also sleeps when idle; waking can take roughly a minute. These are separate platform limits. You can continue with the local Docker route.

Setup says “table already exists”

The tutorial is intended for a fresh schema and runs once. Use the existing sample tables or create a different empty schema. It does not delete or overwrite your tables.
